# 计划模式与权限

Grok 会在执行任何有风险的操作前征求许可，也能在编码前先制定计划。

## 权限

当 Grok 想运行有风险的命令或编辑文件时，它会暂停并询问：
仅允许一次、始终允许此类操作，还是拒绝。

读取始终无需许可：读取文件、搜索和安全的只读命令
（`ls`、`git status`、`grep`、…）从不会触发提示。链式命令会逐段检查——
`ls && rm -rf tmp` 仍会针对 `rm` 提示。

信任此会话？`/always-approve`（或 `Ctrl+O`）会跳过提示。

## 计划模式

对于较大或更模糊的任务，请使用**计划模式**：Grok 以只读方式探索代码库，
设计方案，并在写入任何代码*之前*展示供你批准的计划。

- **`Shift+Tab`**（提示输入框获得焦点时）循环切换模式：普通 → 计划 → 自动审查 →
  始终批准。未启用自动审查功能时，会跳过该模式。
- **`/plan`** 直接进入计划模式；`/plan <task>` 在一步中为该任务制定计划。

计划准备好后：`a` 批准，`c` 对特定行发表评论，`s` 请求更改——Grok
会不断迭代，直到你满意，然后再实现。

一个好习惯：对于“我们到底该怎么做？”使用计划模式，对于“直接做吧”使用普通模式。

## 长时间运行的命令

构建或测试运行占满当前轮次？**`Ctrl+B`** 将其发送到后台——Grok
继续工作，并在完成时通知你（`Ctrl+G` 显示任务面板）。
